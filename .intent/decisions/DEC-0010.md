The Release Manager uses the GitHub REST API to list tags and workflow runs, and `workflow_dispatch` to trigger builds. The fine-grained PAT required is stored as a Vault entry and fetched at use time via `vault:getPassword`.

## Rationale

- The repo is private — the GitHub API requires authentication for all reads
- A fine-grained PAT (Contents: read, Actions: write on `sixbyfive-tcg-admin` only) is the minimum viable scope; no organisation-wide token needed
- Storing the PAT in Vault means it is DPAPI-encrypted at rest on Windows — the same protection as any other credential in the app
- Fetching it at use time (not caching it in memory) means the token is only decrypted when the user is actively on the Release Manager page and triggering an action

## PAT setup (one-time)

1. Create a fine-grained PAT at github.com/settings/tokens/new — scope to `sixbyfive-tcg-admin` only; permissions: `Contents: Read`, `Actions: Read & Write`
2. Save it as a Vault entry (label: "GitHub Release PAT", username: github-actions)
3. In Release Manager settings, enter the Vault entry ID — this is stored in `userData/release-settings.json` alongside the repo/owner/workflow config

## No PAT hardcoded anywhere

The token never appears in code, config files, or `.env`. The only place it exists is in `userData/vault.json` (encrypted) and the user's GitHub account.

## Workflow dispatch ref

The Release Manager sends `workflow_dispatch` against the configured `defaultBranch` (default: `main`). A ref input field in the UI lets the user override (e.g. a feature branch). The CI workflow itself controls what actually gets built; the Release Manager just fires the trigger.

## Feed version check

`latest.yml` is fetched from the public update URL (`https://backendtcg.sixbyfive.com/admin-updates/latest.yml`) without authentication — this file is intentionally public so `electron-updater` can read it from inside packaged builds without a token.
