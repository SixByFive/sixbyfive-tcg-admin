The Status Board checks service health by polling on a timer. The renderer fires `status:checkAll` via IPC; the main process runs checks and pushes results back. There is no WebSocket, no long-poll, no server-sent events.

## Rationale

- The services being checked (TCG API, Kora API, Heimdall SSH) do not push status events — polling is the only option for external services
- A configurable interval (default 60 s) is appropriate for an admin tool; this is not a real-time monitoring dashboard
- The main process must perform checks anyway (to avoid CORS and to access `ssh2`), so the data flow is already IPC-based; adding a WebSocket layer would be complexity for no gain
- Simple pull polling is easy to reason about: the renderer is always in control of when checks run, and the "Check now" button is trivially implemented

## Trade-offs accepted

- Status is not real-time — if a service goes down between polls, the board won't show it until the next check. Acceptable for an internal admin tool where the operator is not monitoring this screen 24/7
- All checks block the main process for their duration (network I/O). This is mitigated by running checks in parallel with `Promise.all` and applying a per-check timeout (default 5 s)

## HTTP checks

`fetch()` from Node.js (Electron 21+ exposes it in the main process). Timeout via `AbortController`. Expects any 2xx; captures response time.

## SSH reachability checks

TCP connect only — no shell opened. Uses `net.createConnection` rather than a full `ssh2` handshake to minimise overhead. If the port is reachable, the service is considered up.
