All three product sections (TCG Admin, Vision Lab, Kora Admin) live in a single `BrowserWindow`. The sidebar gains a top-level section switcher; within each section the existing page navigation continues to work as before.

## Rationale

- A single window is simpler to build and maintain than multiple `BrowserWindow` instances with IPC between them
- Sections share the Electron context bridge and main-process IPC registry naturally
- Users can switch sections without losing scroll position or in-progress state in the other (React subtrees unmount/remount, but router state is preserved via URL)
- Consistent with how most multi-product desktop tools (e.g. VS Code, Figma) structure their UI

## Navigation structure

```
Sidebar
├── [Section switcher — top or bottom of sidebar]
│    ├── TCG Admin  (icon + label)
│    ├── Vision Lab (icon + label)
│    └── Kora Admin (icon + label, locked if no Kora credentials)
│
└── [Section-specific nav items — changes per active section]
     TCG Admin: Dashboard, Users, Orders, Trades, …
     Vision Lab: Dataset, Process, Train, Test, Results, Export, Settings
     Kora Admin: Dashboard, Organisations, Homes, Users, Young People, …
```

## Router

Hash router with section-prefixed paths:
- `/tcg/*` — TCG Admin pages
- `/vl/*` — Vision Lab pages  
- `/kora/*` — Kora Admin pages

The router outlet renders only the active section's component tree.

## Trade-offs accepted

- Existing TCG routes (`/users`, `/orders`, …) must be renamed to `/tcg/users`, `/tcg/orders`, etc. This is a one-time migration with no external impact (hash router, Electron only).
- In-memory state (e.g. an open modal) is lost when switching sections — acceptable for an admin tool.
