Snippet bodies are stored as plaintext in `userData/snippets.json`. No DPAPI encryption is applied.

## Rationale

- Snippets are commands and query templates, not secrets. A bash snippet or SQL query has no access credentials embedded (those go in Vault)
- Encrypting non-sensitive data adds friction (slower read/write, harder to recover if the app breaks) for no security benefit
- Consistent with how the Vision Lab workspace metadata and status targets are stored — local working data lives as plain JSON

## Trade-offs accepted

- If a user accidentally saves a password inside a snippet body, it will be on disk in plaintext. The UI will include a hint ("For passwords and credentials, use Vault") in the add/edit modal to discourage this
- The file is in `userData`, which on Windows is `%APPDATA%\SixByFive Admin\` — a directory that only the current user can read under default Windows ACLs. This is not cryptographic protection, but it's the same level of isolation as browser localStorage

## Boundary

If a snippet body needs to be treated as a secret (e.g. a curl command with an embedded bearer token the user wants to protect), the user should put the token in Vault and store the curl template without the token value in Snippets.
