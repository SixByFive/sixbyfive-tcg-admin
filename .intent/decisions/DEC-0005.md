A new `packages/kora-client` workspace package provides a typed fetch wrapper for the Kora API, following the same structure as `packages/api-client`.

## Rationale

- Keeps API-specific logic out of page components
- Makes the Kora section easy to test in isolation (mock the client, not fetch)
- Consistent with the existing monorepo convention — `packages/api-client` already does this for TCG

## Structure

```
packages/kora-client/
  src/
    client.ts       — KoraApiClient class (token injection, refresh callback, base URL)
    auth.ts         — login(), refresh(), me()
    organisations.ts
    homes.ts
    users.ts
    young-people.ts
    index.ts
  package.json      — name: @sixbyfive/kora-client
  tsconfig.json
```

## Typing strategy

Types are derived from the NestJS DTOs and Prisma models in `H:\care-platform-api\src\`. They are manually mirrored (not auto-generated) for now — the API surface is small and stable enough that codegen overhead isn't worth it yet.

## Trade-offs accepted

- Manual type mirroring can drift from the API; the risk is low for an internal admin tool but should be revisited if the Kora API surface grows significantly
