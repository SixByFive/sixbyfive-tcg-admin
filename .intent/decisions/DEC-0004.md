The login screen has one email + password form. On submit, the credentials are sent to both the TCG API and the Kora API simultaneously. Each that succeeds unlocks its section; each that fails locks its section with a clear "not connected" state. No separate Kora login panel.

## Rationale

- The user (admin) holds accounts on both systems and expects one login action
- A single form is significantly simpler UX than two separate credential panels
- If one backend rejects the credentials (account doesn't exist, wrong password), that section stays locked — the app handles partial success gracefully rather than failing entirely
- The TCG admin key is still entered separately (it's a shared server key, not per-user credentials) — this doesn't change

## How it works

1. User enters email + password and hits Login
2. Both `tcgAuthApi.login()` and `koraAuthApi.login()` are called in parallel
3. Each success stores its refresh token (`tcga_refresh`, `kora_refresh`) and unlocks its section
4. Each failure is silently swallowed — the section shows as "not connected" in the sidebar, not as an error
5. If both fail, the login screen shows a standard "invalid credentials" error
6. After login, the TCG admin key prompt appears if no key is stored (existing behaviour)

## Trade-offs accepted

- If the user has different passwords on TCG and Kora, the single form cannot authenticate both at once — they'd need to use the "Connect Kora" fallback in the sidebar to enter Kora credentials separately. This edge case is acceptable for an internal tool where the same admin controls both systems.
- Both backends must be reachable at login time for both sections to unlock. If Kora is offline, that section stays locked — which is the correct behaviour anyway.
