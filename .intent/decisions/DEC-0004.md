One email + password form. On submit, the credentials are sent to both the TCG API and the Kora API in parallel. Both succeed or both fail — there is no separate Kora login, no "Connect" panel, no per-system credential management.

## Rationale

- The admin controls both systems and has the same credentials on both
- One login is the only acceptable UX for an internal tool you use daily
- No edge-case handling for mismatched passwords — that's an ops problem, not a UI problem

## How it works

1. User enters email + password, hits Login
2. `tcgAuthApi.login()` and `koraAuthApi.login()` fire in parallel
3. Both succeed → both sections unlock, app loads
4. One fails → that section is unavailable but the app still loads; a banner in the locked section explains it
5. Both fail → login screen shows "invalid credentials"
6. TCG admin key prompt appears post-login if no key is stored (existing behaviour, unchanged)

## Persistence

| Key | Value |
|---|---|
| `tcga_refresh` | TCG refresh token |
| `tcga_admin_key` | TCG shared admin key |
| `kora_refresh` | Kora refresh token |
| `kora_base_url` | Kora API base URL (configurable in settings) |
